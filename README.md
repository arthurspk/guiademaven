## :dart: O guia para alavancar a sua carreira

> Maven é o gerenciador de build e dependências mais usado no ecossistema Java: define como o seu projeto compila, testa, empacota e publica, tudo a partir de um único arquivo `pom.xml`. Quase toda vaga de backend Java no Brasil espera que você saiba configurar dependências, plugins e o ciclo de vida de um build Maven — é conhecimento tão básico quanto Git. Este guia reúne documentação oficial, cursos gratuitos e pagos em português e inglês, livros, canais no YouTube, o principal plugins e ferramentas do ecossistema (incluindo o Gradle, a alternativa moderna ao Maven), projetos práticos e um capítulo dedicado a usar IA na prática com Maven — tudo verificado e organizado para quem já sabe Java e precisa dominar o build da sua aplicação.

> Plugins essenciais do ecossistema

- [maven-compiler-plugin](https://maven.apache.org/plugins/maven-compiler-plugin/) — Plugin oficial responsável por compilar o código-fonte Java do projeto.
- [maven-surefire-plugin](https://maven.apache.org/surefire/maven-surefire-plugin/) — Plugin oficial que executa os testes unitários durante a fase `test` do build.
- [maven-shade-plugin](https://maven.apache.org/plugins/maven-shade-plugin/) — Empacota o projeto e todas as suas dependências em um único JAR executável ("fat jar/uber jar").
- [maven-assembly-plugin](https://maven.apache.org/plugins/maven-assembly-plugin/) — Alternativa ao shade para criar distribuições customizadas (zip, tar.gz, jar com dependências).
- [maven-enforcer-plugin](https://maven.apache.org/enforcer/maven-enforcer-plugin/) — Impõe regras no build (versão mínima do Java/Maven, sem dependências duplicadas, etc.) antes de deixar o build passar.
- [maven-release-plugin](https://maven.apache.org/maven-release/maven-release-plugin/) — Automatiza o processo oficial de release: versão, tag no Git e deploy.
- [versions-maven-plugin (MojoHaus)](https://www.mojohaus.org/versions/versions-maven-plugin/) — Verifica e atualiza automaticamente as versões de dependências e plugins desatualizados no `pom.xml`.
- [license-maven-plugin (MojoHaus)](https://www.mojohaus.org/license-maven-plugin/) — Gera e verifica automaticamente os arquivos de licença e cabeçalhos de código do projeto.
- [MojoHaus Maven Plugins Project](https://www.mojohaus.org/) — Organização da comunidade que mantém dezenas de plugins Maven além dos mantidos pela Apache.
- [maven-archetype-plugin](https://maven.apache.org/archetype/maven-archetype-plugin/) — Plugin oficial para gerar novos projetos a partir de templates (archetypes) prontos.

- [maven-pmd-plugin](https://maven.apache.org/plugins/maven-pmd-plugin/) — Roda análise estática de código (PMD) integrada ao ciclo de vida do Maven.

## 🤖 IA na prática

Maven é um alvo comum de erros de configuração — conflito de versões, plugin mal configurado, erro de `dependency scope` — e é exatamente nesse tipo de problema que uma IA ajuda mais: ela lê a árvore de dependências, o stack trace do build e sugere a causa raiz muito mais rápido do que garimpar Stack Overflow.

**Para aprender**
- Cole a saída de `mvn dependency:tree` e peça para a IA explicar por que uma dependência transitiva está entrando em conflito de versão (`NoSuchMethodError`, `ClassNotFoundException` em tempo de execução são sintomas clássicos).
- Peça para a IA **gerar um `pom.xml` mínimo** para um tipo de projeto (API REST, biblioteca, aplicação multi-módulo) e depois explicar o papel de cada seção (`dependencies`, `build`, `plugins`, `properties`).
- Peça exercícios com gabarito sobre o ciclo de vida do Maven (fases, plugins vinculados a cada fase, diferença entre `install` e `deploy`).

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Claude Code](https://code.claude.com/docs/en/overview) ou o [assistente de IA do IntelliJ IDEA](https://www.jetbrains.com/ai/) para gerar configuração de plugins, resolver conflitos de dependência e escrever perfis (`profiles`) do Maven — sempre revisando o que foi gerado antes de commitar.
- Peça para a IA revisar um `pom.xml` grande e sugerir simplificações: dependências não usadas, versões que podem ser centralizadas em um `dependencyManagement`, plugins redundantes.
- O [Amazon Q Developer](https://aws.amazon.com/q/developer/) também analisa projetos Java/Maven diretamente na IDE, incluindo sugestões de atualização de dependências vulneráveis.
- Depois de aceitar qualquer sugestão, rode `mvn verify` (ou `mvn clean install`) e confira se o build passa — builds Maven falham rápido quando algo está mal configurado, o que ajuda a pegar erros gerados por IA antes que cheguem ao CI.

**Limites e boas práticas**
- IA erra e inventa nomes de `groupId`/`artifactId`/versões que não existem no Maven Central. Sempre confirme em [central.sonatype.com](https://central.sonatype.com/) antes de colar uma dependência sugerida.
- Não cole credenciais do `settings.xml` (senhas de repositório privado, tokens) em ferramentas de IA.
- Entenda o que você aceita: em entrevista técnica e em produção, o build — e os bugs — são seus.

## 🎓 Certificações

Não existe uma certificação oficial da Apache dedicada exclusivamente ao Maven — a ferramenta é, na prática, avaliada dentro das certificações mais amplas de Java do mercado.
- [Certificações Oracle](https://www.oracle.com/br/education/certification/) — Portal oficial de certificações da Oracle, incluindo as trilhas de certificação Java (base necessária para qualquer vaga que peça Maven).
- [Credly — badges da Oracle](https://www.credly.com/organizations/oracle/badges) — Página oficial para emitir e verificar badges de certificações Oracle, incluindo Java.
